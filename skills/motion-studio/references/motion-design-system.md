# Дизайн-система движения: MOTION.md, правила качества, аудит

Главный вывод всех источников: **дизайн-система решает всё**. Без неё Claude выбирает свои цвета, шрифты и «AI-вкус по умолчанию». С ней тот же однострочный промпт выходит в вашем стиле.

## 1. Два файла бренда (процесс brand-intake)

**Интервью — два пакета вопросов (ждать ответ после каждого):**
1. Как называется бренд и что делаете — одной строкой? 2. Для кого (одно предложение про зрителя)? 3. Что продвигаете в роликах (продукт/оффер, реальная ссылка)? 4. Что зритель должен почувствовать в первую секунду (до трёх: спокойно, премиально, игриво, срочно, технично, тепло, смело)?
5. Цвета hex, названия шрифтов, файлы логотипа (SVG/PNG) — или «возьми с моего сайта» + ссылка. 6. 3–5 кадров-референсов моушна, который нравится (Dribbble, Pinterest, свои работы) → папка `examples/`. 7. Одна вещь, которую ваш моушн не должен делать никогда.
Пустой ответ — переспросить один раз, потом дальше. Никогда не заполнять пробел догадкой.

**brand.md** (до 300 слов, в корне проекта): Name and what we do · Audience · What we promote (link) · The feeling · Assets (hex — набранные или снятые с названного источника, шрифты, файлы лого) · Never.

**MOTION.md** — пишется ТОЛЬКО по кадрам из `examples/` (шаблон: `templates/MOTION.template.md`), обязательно 7 разделов: цвета с ролями · шрифты и кегли · тайминг (вход/удержание/уход) · движение (fps, easing, «рукотворность») · фактура и отделка · 5 запретов · один пример «как правильно» по шотам. Где не видно — писать **ASK ME**, а не угадывать. Показать файл перед сохранением. Цвета из brand.md важнее снятых с кадра (с JPEG hex «плывёт» на несколько единиц).

**Правило в CLAUDE.md проекта (дословно):**
```
Before designing, generating or animating anything, read MOTION.md in full.
Every colour, font, timing and motion value comes from that file.
The file sets the look, not the ambition. When I say go all out, go all out.
If something I ask for is not covered there, ask me rather than choosing for yourself.
When you have finished, check your own frames against MOTION.md, fix what fails, and only then show me.
```
Уроки: смешанные кадры → смешанный стиль (файл назовёт все «луки» и спросит, какой главный — выбрать один или привязать лук к типу задачи); без строки «file sets the look, not the ambition» результат «слишком вежливый»; остановка с вопросом ASK ME — это файл работает. Проверка: один и тот же промпт в пустой папке и в проекте — оба «go all out», но только второй «ваш».

Пример реального MOTION.md (бренд «АИ ЭКСПЕРТ», из рилса): Стиль — чёрный, белый, оранжевый. Шрифты: заголовок Gilroy Regular, подзаголовок Gilroy Light, наборный Gilroy Regular, интерлиньяж 135 %. Цвета: #0A0A0A фон, #FFFFFF текст, #FC9510 акцент (градиент → #E37115). Тайминг: 0,35 с вход элемента (ease-out, без отскока) · 1,5–2 с смена картинки (одна мысль — один кадр) · 0,5 с пауза на акценте после ключевого слова.

## 2. Тайминг и движение по умолчанию (если MOTION.md молчит)
- Вход элемента 0,3–0,4 с, ease-out `cubic-bezier(0.16,1,0.3,1)`, без отскока; уход быстрее входа (0,2–0,25 с, ease-in).
- Одна мысль — один кадр, 1,5–2 с на прочтение; пауза 0,5 с после ключевого слова.
- Стаггер элементов списка/букв — на долю такта (2–4 кадра), а не все разом (всё вместе = «слайд»).
- Петля (loop) 8 с: движение 0–2,2 с · удержание 2,2–6,6 с (что-то маленькое живёт: курсор, прогресс, вторая волна света) · возврат 6,6–8,0 с · кадр 8 = кадр 0 пиксель-в-пиксель.
- Пружины (spring) вместо твинов для физичных вещей (выемка, карточки); разный damping у разных объектов; для «рукотворного» — движение на двойках (24 fps, поза держится 2 кадра).
- Передавать скорость между движениями: следующее движение стартует, не дожидаясь полной остановки предыдущего (иначе цепочка «замирает между шагами»).
- Камера: один медленный ровный наезд/пролёт, без тряски и вращений; push-in на экраны продукта.

## 3. Правила дома (все источники вместе)
1. **Факты первыми.** Каждое имя, дата, число — из утверждённого списка. Нет данных — спросить. Демо-цифры — плашка «пример»/«Illustrative data» на каждом кадре. Цель не выдавать за результат. Не округлять, не добавлять «+».
2. **Ваш бренд, а не «средний».** Цвета и шрифты — из MOTION.md или от вас; без них — спросить.
3. **Запрещённые дефолты:** typewriter в заголовках (печать — только внутри поля ввода UI), glow, bounce, градиенты на тексте, фиолетово-синие фоны.
4. **Хук — первые 3 секунды.** Пустой первый кадр — вырезать. Если первые 3 с не остановят ваш собственный палец — переделать их до остального.
5. **Проверка перед экспортом:** кадр из середины каждого шота — обрезанный текст, наложения, неверные факты.
6. **Только реальные ассеты.** Лого и скриншоты — из ваших файлов, никогда не перерисовывать по памяти (лого чужого бренда — набрать название шрифтом).
7. **Премиум = один объект меняет форму** (кнопка → плеер, бары → линия, карточка → окно), а не fade картинки в картинку; полупрозрачный «призрак» исходного состояния; общий элемент (заголовок) перемещается, а не дублируется.
8. **Разнообразие:** соседние сцены не повторяют раскладку; новые движения в каждом ролике (не переиспользовать прошлые).
9. **Карточки и предметы, а не линии:** одинокая полоска/линия по экрану читается статично — сцены строить из карточек, картинок, объектов в глубине. Сетки симметричны (равные размеры и отступы); лого заполняет свою карточку.
10. **Звук обязателен** для эксплейнера/промо (бит-подложка, удар на каждый новый шот, подъём на финальной фразе); голос сверху — если не слышно, глушить партитуру.
11. **Сквозной мотив** держит ролик (съёмочная площадка «ДУБЛЬ 01…10», ночное небо из точек…).
12. **Вертикаль под телефон:** заголовок ≥84 px, важный текст ≥44 px при ширине 1080; поля ≥80 px по бокам, ≥100 px сверху/снизу; safe zone рилса — текст и лого в прямоугольнике x 120–840, y 260–1360 (справа кнопки, снизу подпись и навигация; по гайду Meta и замеру saint4ai), проверяется `scripts/qa-fit.mjs`; мелкие подписи делать вдвое крупнее, чем кажется нужным.
13. **Честный предел:** фотореалистичный человек кодом не рисуется — нужен генератор изображений/видео.

## 4. Аудит движения «как у Apple» (принципы скилла apple-design, Emil Kowalski)
Установка: `npx skills add emilkowalski/skills --skill apple-design`. Промпт: «Use the apple-design skill to audit this animation. Give me a ranked list of everything that feels off, worst first.» → исправлять по одному.
Что он ловит (пример реального ответа): (1) цепочка движений замирает между шагами — точка сжимается/тянется на старте и в конце, камера стартует с нуля без передачи скорости; (2) перелёт (overshoot) там, где ничего не бросали — отскок у линейки и первой точки (по умолчанию без перелёта); (3) скачок яркости на весь экран — белая вспышка 85 % поверх чёрного (избегать резких скачков яркости).
Ключевые принципы: движение передаёт причину и следствие; прерываемость и сохранение скорости; пружины без лишнего перелёта; ease-out на входе; ничего не появляется «из ниоткуда» (пространственная непрерывность); сдержанность — меньше одновременных движений; reduced-motion — замена на быстрые фейды.
Родственный набор: emilkowalski/skills (animate, improve-animations, review-animations, emil-design-eng) — плавность, скорость, длительность.

## 5. Настоящие UI-компоненты (21st.dev)
Если в ролике продукт — не давать Claude рисовать кнопки/карточки с нуля (угадывает отступы → UI выглядит фейком). На 21st.dev у каждого компонента есть «Copy prompt». Один раз добавить правило в CLAUDE.md:
```
Whenever I paste a component prompt or third-party component code, treat it as a structural donor only. Keep its engineering. Replace its demo copy with my real copy, and translate every colour, border, shadow, font and timing to MOTION.md.
```

## 6. Как давать правки (заметки как дизайнеру)
- Одна правка — одна вещь; назвать часть и что не так; Claude меняет только её.
- Говорить, как ощущается, а не как чинить: «выглядит не очень премиально» работает.
- Указывать момент: «текст в начале», «на 3-й секунде».
- Шаблон: «[файл] почти готов. Исправь только одно: [что]. Движение, тайминг и петлю оставь как есть. Скажи, что поменял.»
- Рабочие заметки из практики: «текст в начале недопродаёт то, что дальше» · «голос не слышно за эффектами» · «не выглядит премиально» · «это не мои фирменные цвета» · «долго идёт к раскрытию, нужна точка после “in your voice”» · «ненавижу голос — давай просто хороший саундтрек».
