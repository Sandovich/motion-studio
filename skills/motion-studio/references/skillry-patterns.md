# Что работает в 475 промптах Opus 5.5 (разбор библиотеки Skillry)

Источник: skillry.dev/ai-videos/opus-5-5 (475 роликов с исходными промптами авторов; категории Motion graphics 288, Games 70, Explainers 62, 3D scenes 55). Здесь — выжимка закономерностей своими словами. Полный текст любого промпта — по ссылке в `skillry-index.md` или собрать всю библиотеку локально: `python scripts/fetch-skillry-prompts.py` (из репозитория motion-studio).

## Статистика
- Технологии в роликах: Canvas 335 · SVG 193 · Three.js 140 · GLSL 100 · GSAP 81 · CSS 61 · Web Audio 32 · WebGL 9.
- Частые слова в промптах: «go all out» (103), «showreel» (103), «15-second» (85+10), «Remotion» (62), «3D» (59), «sound» (56), «music» (50), «camera» (34), «HyperFrames» (27), «brand» (27), «loop» (26), «one prompt» (18).
- Медианная длина промпта ~200 знаков: большинство роликов сделано КОРОТКИМ промптом + 1–3 правками. Длинные (>500 знаков, 92 шт.) — для точного контроля бренда/сцен.

## 10 типовых каркасов (структуры, по которым пишутся сильные промпты)

**1. «Шоурил» (самый частый).** Роль мирового моушн-дизайнера + «покажи, на что способен, как шоурил для резюме» + длительность + «go all out». Дальше авторы добавляют тему/бренд и/или список техник (кинетическая типографика, плавные переходы, 2D и 3D, абстрактная геометрия, флюиды, частицы, искажения, маски, композитинг, свет, глубина, бесшовная камера) и требование «арт-дирекции, а не набора эффектов: каждый шот естественно переходит в следующий». Вариант: тот же промпт + тема-манифест («перепиши мои мысли умнее»).

**2. «Промо продукта из его же сайта/кода».** Роль: старший моушн-дизайнер + продакт-дизайнер + инженер Remotion. Шаги: сначала прочитать лендинг/репозиторий/токены дизайна/лого (обвести лого в SVG) → написать ролик как одну историю (почему рынок важен → почему больно сегодня → как продукт решает → что получаешь) в 4–5 сценах с короткими заголовками → анимировать как премиум-фильм (кинетика по словам, пружины, плавные наезды/панорамы, глубина, элементы «собираются в бит», а не просто появляются) → держать сцену достаточно для чтения → один мягкий звук на каждое появление, иначе тишина → финал: анимированное лого + слоган + URL → отрендерить, самому проверить кадры, исправить наложения/обрезку/спешку до показа. Варианты с антиподами: «это НЕ шаблонный SaaS-эксплейнер, НЕ обзор фич», ориентиры «Apple-запуск × премиум-финтех × редакционный моушн × сдержанная подача как у Stripe», желаемая реакция зрителя одной фразой.

**3. «UI-моушн одной формой» (Dribbble-уровень, повторяется у десятков авторов).** Блоки `<inputs> <direction> <structure> <build>`: (inputs) спросить 8–12 состояний UI, ч/б или один акцент, трек ~120 BPM; (direction) одна форма без склеек — каждое состояние это тот же элемент, меняющий размер/радиус/цвет, контент сменяется коротким размытием; курсор делает реальные клики и перетаскивания; тёплый серый холст, ч/б компоненты, один UI-шрифт (Geist); пружины, максимум крошечный перелёт; камера зумит, чтобы состояние заполняло кадр; последний кадр = первый (петля); запреты: пружинистый easing, частицы, glow, градиенты на интерфейсе, разнобой иконок, пустое время, «шаблонность»; (structure) 120 BPM, 7 тактов, что-то на каждую долю: кнопка → лоадер → галочка → dynamic island → плеер (морф play/pause) → скраб прогресса → слайдер громкости тянется за максимум → тумблер в долю → ручка становится жидким индикатором вкладок → вкладки раскрываются в рисующийся график с тултипом → схлопывается в ⌘K → ввод фильтра → enter → тост → обратно в кнопку; (build) один HTML квадрат 1440, всё вычисляется в `seek(t)`; пружины — аналитическое переходное решение, смена цели = сумма пружин (остаётся функцией времени); у индикатора вкладок два края на разных пружинах — передний край убегает вперёд; перетаскивание = прямое управление, по отпусканию пружинит назад; звуки UI синтезировать кодом.

**4. «Эксплейнер с фактами» (автономно).** Тема + стиль (напр. сказочный, у героя есть характер) + «должно выглядеть как студия, а не “AI-видео”» + «рендер кодом кадр за кадром, без видеогенераторов» + ориентиры (кинетические рилсы, бесконечные зумы, дата-эксплейнеры The Pudding / 3Blue1Brown: чёткость, связная дизайн-система, ОДНА сильная формальная идея на сцену) + точность: симулировать настоящее явление, а не рисовать его, реальные числа с честной неопределённостью, юмор и визуальные гэги, колбэки + поставка: формат/fps/точная длина, голос (лучший доступный TTS), вшитые субтитры (смотрят без звука), оригинальная партитура по сценам, звук синхронно с действием. Режим «работай автономно до конца, не задавай вопросов, в конце расскажи, что решил».

**5. «Кинетическая речь / типографика как архитектура».** Точная длительность и название; дословный текст речи в точном порядке; арт-дирекция hex-кодами (фон/бумага/акцент) + роли шрифтов (контрастный антиква для речи, тяжёлый гротеск для «несущих» слов, моно для таймкодов); запреты клише; ЦЕНТРАЛЬНОЕ ВИЗУАЛЬНОЕ ПРАВИЛО: у слов роли (слово-перемычка, слово-груз на тросах, слово-опора, слово-проём, слово-платформа) и они рождаются из самих букв; раскадровка по секундам; финальная фраза «стоит» на том, что построили предыдущие.

**6. «Сцена с персонажами и картой локации».** Контекст сцены, затем КАРТА ЛОКАЦИИ с физическими размерами и пропорциями («иллюминатор ~50 см: голова занимает половину диаметра»), описание интерьера/экстерьера, позиции камер (снаружи/изнутри), число склеек и длительность. Нужна, когда важна пространственная правда (тут обычно помогают генераторы изображений для персонажей).

**7. «Музыкальный клип по треку».** Дан трек/ссылка + референс-стиль; «пройди end-to-end самостоятельно; подумай, как лучше визуально выразить каждую строку; не обязательно буквально — отсылки, лор, пасхалки»; «бумажная фактура JS-анимации, но двигай эстетику куда хочешь, учитывай дух времени»; персонажи через стиль-лист; подрезать хвост трека; кредиты в конце.

**8. «Тизер с одной камерой» (HyperFrames).** Ландшафт ~27 с; «медленно и дорого: одна непрерывная камера над одним рабочим столом Mac, без жёстких склеек; наезды/отъезды/панорамы 1,5–3 с на мягких ease-in-out — вдвое медленнее, чем по умолчанию»; motion blur на быстрых движениях, лёгкое зерно, огромный курсор macOS; копирайт строчными как в посте; покадровый сценарий: фраза по словам с цветной шторкой (компонент реестра), список из 30 пунктов крутится быстро и медленно садится на нужный, «?» через 0,2 с; окна реальных приложений влетают из-за камеры; пролёт сквозь окна; тугой кадр на «чёлку» → морф в пилюлю → панель.

**9. «Быстрый эксплейнер-промо по шаблону с переменными».** 15 с, HyperFrames + GSAP, без голоса и футажа; стиль: светлый «бумажный» холст, заметки маркером, которые рисуются, реальная физика, огромная кинетическая типографика, жёсткие переключения светлый/тёмный, новая мысль каждые 1,5–2 с, звук на каждый удар; КОПИ из документов позиционирования ({{ONE_LINER}}, {{AUDIENCE}}, {{WHAT_IT_DOES}}), «называй то, что продукт узнаёт, а не абстракцию»; ПРАВИЛА: никакого «хрома» (скраббер, таймкод, fps, шапки), никакого жаргона аниматора на экране, никаких выдуманных результатов, стоп-слова, настоящий лого + словесный знак; РЕМЕСЛО: цвета холст/чернила/2 акцента, Anton для кинетики, Caveat-рукопись через stroke-dashoffset; настоящий easing, сжатие-растяжение, стаггер, перекрытие, onion skin, смаз, доводка; сначала проверить реестр готовых блоков; все from-состояния задать в t=0 (seek-safe), никогда не перекрывать уход; одно главное движение на переход, без шаблонных push/slide/rotate; музыка секциями (барабаны выпадают на тёмном переключении, возвращаются на типографике и лого); SFX: попы, скрип ручки, whoosh, саб-удар на лого; только CC0/сгенерированное с логом источников; мастер −14 LUFS / −2 dBTP, перемерить после AAC.

**10. «Интерактивная игра/демо/вау-эффект в одном HTML».** Не видео, но та же школа: один файл, стек (Three.js/WebGL/Canvas/Web Audio), детальная арт-дирекция и пошаговые «фазы шоу» (подготовка → нарастание → заряд → взрыв → раскрытие/итог), запреты на дешёвые приёмы (обводка «раздутой изнанкой», кислотный пересвет на весь экран, конфетти по всему кадру), требование «протестируй, исправь все баги, потом улучшай визуал, пока не станет максимально реалистично», совет: эффорт на максимум и время (~1,5 ч), потом «что выглядит наименее реалистично? Исправь».

## Приёмы мастерства, которые повторяются у лучших авторов
- **Контакт-лист вместо просмотра рендеров:** отрендерить ~20 стоп-кадров и склеить в один лист — весь монтаж видно с одного взгляда ДО рендера видео.
- **Субтитры измеряются в реальном шрифте и ужимаются под 9:16 safe zone** — ничего не прячется под кнопками TikTok/Reels.
- **Сетка 120 BPM:** каждая склейка в долю — музыку потом легко подложить.
- **Одна кодовая база → разные версии:** 30/15/6 с и 16:9/9:16 — это просто разные списки сцен.
- **Импорт CSS-токенов и шрифтов сайта** → ролик в той же дизайн-системе, что и продукт.
- **«Моя роль — сказать, что ощущается не так»:** человек даёт ощущения, модель чинит.
- **Самокритика по кадрам:** отрендерить кадр → разобрать как VFX-супервайзер (можно vision-моделью) → исправить → повторить (у одного автора ~40 итераций).
- **Звук из самой сцены:** громкость треска огня = яркость пламени в кадре; UI-звуки синтезировать numpy; саундтрек синусами и шумом в Python.
- **Пружины аналитически** (а не симуляцией) → детерминированно и seek-safe; несколько пружин суммируются.
- **Вдвое медленнее дефолта** для «дорогого» ощущения; motion blur только на быстрых движениях; лёгкое зерно.
- **Реальные данные и реальные экраны:** Claude сам гоняет симулятор iOS и записывает экраны, пишет SQL-запросы для настоящих цифр.
- **Проект как софт:** у сложных работ — модульные тесты, браузерные тесты, детерминированный захват кадров (один кадр дважды = те же пиксели), саб-агенты.
- **Сначала показать стоимость:** перед платными генерациями — список генераций с ценой в кредитах и ожидание «ок»; скриншоты перед каждым дорогим шагом.
- **Эффорт:** авторы отмечают Opus 5.5 с effort max/medium; сложные вещи — до 1–2 часов работы модели.
- **Ссылки на референсы:** 1–2 референс-видео и заранее список обязательных фич для сценария заметно улучшают результат; повторный запуск со «showreel»-промптом поверх своего брифа даёт резкий скачок качества.
